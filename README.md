# cofa-kit

AI 코딩 에이전트(Codex)와 함께 실무 과제를 풀 때 쓰는 개인 작업 지침과 템플릿입니다.
**특정 과제의 해답이나 결과물 코드는 없습니다.** 작업 방식, 판단 기준, 기록 양식만 담았습니다.

## 핵심 생각
- 잘못 이해한 문제를 빨리 푸는 것이 가장 비싼 실수다. **문제 정의와 질문이 먼저다.**
- 완료는 느낌이 아니라 **실행한 증거**로 판단한다.
- AI는 선택지와 초안을 내고, **판단과 책임은 내가 진다.** 그 판단을 기록으로 남긴다.

## 구성
| 파일 | 용도 |
|---|---|
| `AGENTS.md` | 에이전트가 따르는 원칙: 우선순위, 역할 분담, 작업 흐름, 완료의 정의, 안전 규칙 |
| `PLAYBOOK.md` | 작업 중 내가 찾아보는 문서: 시간 규칙, 소통, 범위 조정, 막혔을 때 대처 |
| `RUNBOOK.md` | **시험 중 보는 한 장**: 창 구성, 순서와 관문, 기다리는 동안 할 일, 막혔을 때 |
| `PROMPTS.md` | RUNBOOK 구간 순서의 프롬프트. 고정 문장과 내 말로 쓰는 대화 예시를 구분 |
| `skills/requirements-check` | 시작할 때 요구사항, 제약, 질문을 정리하는 절차 |
| `skills/research-loop` | 답이 정해지지 않은 계산 문제에서 가설을 세우고 실측으로 비교하며 개선하는 절차 |
| `skills/user-verify` | 구현이 끝나면 내가 기준을 정하고 직접 확인하는 검증(PV) 절차 |
| `skills/code-tour` | 초보자가 코드 구동 방식을 내 말로 설명할 수 있게 하는 안내 절차 |
| `skills/verify-and-wrapup` | 마무리할 때 최종 점검과 문서화를 하는 절차 |
| `templates/WORKLOG.md` | 요구사항, 결정, AI 제안 수정, 검증 기록 양식 |
| `setup.sh` | 지침, 스킬, 기록 양식을 과제 폴더에 설치한다 (있는 파일은 덮어쓰지 않는다) |

## 사용법
```
cd [과제 폴더]
git clone https://github.com/ccmct/cofa-kit.git /tmp/cofa-kit-ccmct
bash /tmp/cofa-kit-ccmct/setup.sh
codex
```
과제 폴더에 `AGENTS.md`, `cofa-skills/`, `cofa-guide/`, `WORKLOG.md`가 생깁니다. 내가 AI와 함께 쓴 지침과 안내이므로 작업물과 함께 남겨 둡니다.

## 만든 방식
AI와 함께 초안을 만들고, 내 수준과 작업 방식에 맞게 골라 다듬었습니다.

## 변경 기록
- v5: 답이 정해지지 않은 문제를 연구하는 구조로 개편. 시험 중 보는 한 장(RUNBOOK) 추가, 분 단위 시간표 대신 순서와 관문, 기다리는 동안 할 일. research-loop 스킬(평가 도구 준비, 알아가기, 가설 → 실측 → 내 결론 → 숫자로 담당자 확인, 멈추는 조건, 끝내기). 창 2~3개(작업, 점검, 분석)와 읽기 전용 창의 분석 허용. 프롬프트를 고정 문장과 대화 예시로 구분. 검증에 처음 보는 잘못된 입력과 전체 실행 시간. WORKLOG에 목표와 지표, 평가 세트, 실험 기록
- v4.2: 계획을 WORKLOG 계획 칸에 적고, 단계 구현 프롬프트는 매번 같은 문장으로 계획의 할 일과 확인 방법을 따르게 변경. 확인 방법은 "무엇을 넣으면 → 무엇이 나와야" 형태로, 하나는 화면에서 직접 보는 것
- v4.1: 과제 폴더 찾는 방법, 새 터미널 탭과 두 번째 Codex도 과제 폴더에서 켜고 지침 적용을 확인하는 절차 추가. 설치가 끝나면 과제 폴더 경로를 알려 줌
- v4: 요구사항 점검에 데이터 기본 집계와 뜻이 둘 이상인 문구 찾기 추가. 계산이 큰 문제는 단순한 기준선을 먼저 만들고 지표로 비교. 규칙이 많은 결과는 별도 검사기로 확인. 구현 단계마다 쉬운 말 2줄과 내 한 줄 설명을 쌓아 code-tour로 잇기. 최소 버전 뒤 확인 대기를 모아 2차 질문
- v3: 실전 환경을 한 번 겪고 보강. 설치 위치를 홈 폴더 전역 설정에서 과제 폴더로 변경(쓰기 제한 환경 대응, AI에 준 지침이 작업물과 함께 남도록). 과제가 정한 제출 파일·양식 우선, 제출 문서에 작업 메모 남기지 않기. 담당자가 정하지 못한 기준은 선택지를 제안해 확인받고 안 되면 설정 옵션으로 두기, 확인 대기 항목을 모아 다시 묻기. 요구사항 점검에 제약 목록과 정해지지 않은 값 추가. 검증에 실행 안내대로 다시 띄우기와 내가 정한 기준 추가. 배포를 요구하는 과제용 점검표. 작업 창과 읽기 전용 점검 창 2개 운영. WORKLOG 요약 길이 제한. 서술형 리허설을 제출물 기반 유형으로 정리
- v2: 규칙마다 이유를 붙이고 우선순위, 역할 분담, 완료의 정의를 추가. 플레이북은 실제로 찾아볼 내용만 남김. 프롬프트를 타이밍 순서로 재구성하고 확인 문제 대비 흐름 추가. 시간 규칙을 180분 타이머 기준으로, 인계(handoff)와 장애 대응 항목 추가. 초보자가 판단할 수 있도록 선택지 제시 방식과 판단 기준 추가. 요구사항 맞춤 설계(근거 추적, 과설계 점검), 자동 진행 금지, 내가 하는 검증(PV)과 user-verify 스킬, 시작 점검(Flask 대체), 합의문과 여러 담당자 규칙, code-tour 스킬 추가
- v1: 작업 흐름, 기록 양식, 프롬프트 틀, 설치 스크립트

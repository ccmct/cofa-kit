# 요구사항 점검

코드를 쓰기 전에 아래 순서대로 한다.

0. **시작 점검**: 아래를 실행하고 결과를 WORKLOG "환경"에 적는다. AGENTS.md 6번의 A/B/C 중 무엇인지 말한다.
   ```
   python3 --version
   python3 -c "import flask; print('flask', flask.__version__)"
   python3 -m pytest --version
   git --version
   ```
   Flask가 없으면 `pip install flask`를 **한 번만** 시도한다. 실패하면 C(파이썬 기본 기능만)로 정한다.
1. 과제 문서와 제공 파일 목록을 전부 확인한다. 읽은 파일 이름을 나열한다. 담당자가 여러 명 보이면 이름과 역할을 적는다.
2. 과제 목표를 한 문장으로 쓴다.
3. 필수 요구사항을 R1, R2… 번호로 만든다. 각 항목에 출처(문서의 어느 부분, 누구의 DM 등)를 붙인다. 이후 모든 파일·기능은 이 번호로 근거를 댄다.
4. 문서에 직접 쓰여 있지는 않지만 담당자가 당연히 기대할 만한 조건을 따로 적는다. 예: 빈 입력 처리, 새로고침 후 유지, 모바일 화면, 오류 메시지.
5. 모호한 점 가운데 결과에 큰 영향을 주는 것을 3~5개 고른다.
6. 담당자에게 보낼 DM 초안을 쓴다. 질문마다 기본안을 붙여 "A로 진행하려는데 괜찮을까요?" 형태로 쓴다. 답이 늦어도 기본안으로 작업을 계속할 수 있게 하기 위해서다.
7. 결과를 WORKLOG.md의 "요구사항"과 "가정" 칸에 반영한다.
8. 담당자 답이 오면 **합의문 5줄** 초안을 쓴다: 이해한 문제 / 왜 생기나 / 성공 기준 / 만들 것·안 만들 것 / 제약. 사용자가 다듬어 담당자에게 보낸다. 담당자끼리 말이 다르면 차이를 표로 정리하고 결정권자에게 물을 DM 초안을 쓴다.

이 단계에서는 코드나 파일을 새로 만들지 않는다. WORKLOG.md 갱신만 예외다.

# 내가 하는 검증 (PV)

AI가 만든 테스트를 AI가 통과시킨 것은 사용자의 검증이 아니다. 아래 순서로 **사용자가 판단할 수 있는 검증 자료**를 만든다. 이 단계에서는 코드를 고치지 않는다.

1. **기준 목록**: WORKLOG의 요구사항(R번호)과 담당자 답을 모두 나열한다. 하나도 빠뜨리지 않는다.
2. **기대 결과 구하기**: 항목마다 기대 결과를 **원본 데이터와 담당자 답에서 직접** 구한다. 작성한 코드나 함수를 쓰지 않는다. 계산 과정(어느 행, 어느 값, 어느 기준)을 한 줄로 적는다.
3. **실제 결과**: 앱을 실제로 실행해서(화면, curl, 테스트) 결과를 얻는다.
4. **비교**: WORKLOG "PV 검증표"를 채운다. 칸은 요구사항·담당자 답 / 확인 방법 / 기대 결과 / 실제 결과 / 일치 / 내가 직접 확인.
5. **다른 방법으로 한 번 더**: 가장 중요한 결과 하나는 코드와 다른 방법으로 확인한다. 예: 원본 파일에서 해당 행만 골라 직접 세기, 손 계산.
6. **경계와 장애**: 경계값(기준과 같은 값, 기간의 시작과 끝), 빈 값, 잘못된 입력, 재시작을 최소 하나씩 확인한다.
7. **사용자 확인 항목**: 미리보기에서 사용자가 **직접 눈으로** 확인할 항목 2개와 보는 방법(주소, 어디를 보면 되는지, 기대 화면)을 알려 준다.
8. **보고**: 일치하지 않는 항목을 맨 위에 둔다. 각각 원인 후보와, 그것이 코드 문제인지 현장 규칙이 애매해서 생긴 문제인지(→ 담당자 확인 필요) 구분한다. 고치기 전에 사용자의 결정을 기다린다.

사용자가 "미리보기에서 ~를 직접 확인했어"라고 하면 PV 검증표의 "내가 직접 확인" 칸에 사용자 표현 그대로 적는다.

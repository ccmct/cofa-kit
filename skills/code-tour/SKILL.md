# 코드 투어 (초보자용)

사용자는 파이썬 기초 문법만 읽을 수 있다. 목표는 **사용자가 보지 않고 5분 안에 "이 코드가 어떻게 돌아가는지"를 손으로 쓸 수 있게** 하는 것이다. 코드를 고치지 않는다.

1. **한 장 지도**: 실행 흐름을 번호 목록 5~8줄로 쓴다. 각 줄은 `파일 → 함수` + 쉬운 말 한 문장이다.
   예: "1. `python app.py`를 실행하면 `app.py` 맨 아래 `app.run`이 서버를 켠다"
   다음 흐름을 반드시 포함한다.
   - 서버가 켜질 때 일어나는 일
   - 사용자가 화면을 열 때(대표 요청 하나) 어떤 함수가 어떤 순서로 불리는지
   - 데이터를 어디서 읽고 어디에 저장하는지
   - 화면에 결과가 그려지는 곳
2. **핵심 줄 3곳**: 문제 고유 규칙이 들어 있는 코드(예: 판정 기준, 묶는 기준, 기간)를 골라 각각 최대 5줄씩 인용한다. 줄마다 쉬운 말 번역을 붙인다. 파일 이름과 함수 이름을 함께 적는다.
3. **나오는 문법만 풀이**: 이 코드에 실제로 나오는 파이썬 문법만 골라 한 줄씩 설명한다. 예: `def`, `return`, `for`, `if`, 리스트 `[]`, 딕셔너리 `{}`, `with open`, `@app.route`, `sorted(key=...)`. 나오지 않는 문법은 설명하지 않는다.
4. **에디터에서 직접 보기**: 사용자가 웹 IDE에서 직접 열어 볼 곳 3개를 알려 준다. 파일, 함수 이름(검색어), 그곳에서 무엇을 확인하면 되는지.
5. **예상 질문 4개**: 구동 방식 유형으로만 낸다. 예: "화면을 열면 어떤 순서로 처리되나요?", "데이터는 어디에 저장되나요?", "[핵심 규칙]은 코드 어디에서 처리하나요?", "서버를 다시 켜면 데이터는 어떻게 되나요?" 답은 쓰지 않는다.
6. 사용자가 직접 쓴 설명을 보내면 **사실과 다른 부분만** 짚는다. 문장은 고치지 않는다. 빠진 단계가 있으면 "빠진 단계: ○○"로만 알려 준다.

WORKLOG "코드 흐름 메모" 칸에 1번 지도와 2번 핵심 줄 위치를 적는다. 사용자가 쓴 설명은 사용자 표현 그대로 "내 설명" 칸에 적는다.

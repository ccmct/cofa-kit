# 최종 검증과 마무리

1. **요구사항 대조**: WORKLOG.md의 요구사항을 하나씩 보면서 충족, 부분 충족, 미충족을 표시한다. 근거로 구현 위치(파일·함수)와 실행 결과를 붙인다. 확인 대기로 남은 항목도 함께 보여 준다.
1-1. **설계 점검**: 지금 있는 파일·함수·기능·라이브러리를 모두 나열하고, 각각 근거가 되는 요구사항 번호나 담당자 답을 붙인다. 근거 없음, 요구사항보다 큼, 요구사항인데 빠짐을 표시해 WORKLOG 설계 점검표를 갱신한다. **지우기 전에 목록을 보여 주고 내 확인을 받는다.**
2. **처음부터 실행**: 서버를 끄고 실행 안내에 적을 명령(실행 스크립트) 그대로 다시 띄운다. 띄워지는지 확인한다.
2-1. **배포 점검** (과제가 배포·운영 환경을 전제로 요구할 때만. 요구하지 않은 항목은 만들지 않는다)
   - 설정값과 비밀값이 코드에 없고 환경변수로 들어가는가, 예시 파일(예: `.env.example`)이 있는가
   - 서버를 재시작해도 데이터와 결과가 남는가
   - 빈 저장소에서 처음 시작해도 필요한 구조와 초기 데이터가 준비되는가
   - 상태 확인 주소(헬스체크)가 응답하는가
   - 컨테이너 파일(예: `Dockerfile`)이 있다면 실제로 빌드하고 실행해 봤는가
   - 실제 비밀번호나 키가 제출 파일 어디에도 없는가
3. **동작 확인**: 핵심 기능마다 아래를 실제로 실행하고 결과를 보여 준다.
   - API는 `curl` 요청과 응답
   - 화면은 미리보기에서 확인할 순서
   - 경계와 오류 케이스: 빈 값, 잘못된 형식, 없는 항목, 새로고침
   - 장애 상황: 입력 데이터가 없거나 형식이 깨졌을 때, 서버를 재시작했을 때 어떻게 되는지. 위험한 실험은 복사본으로 하고, 제공 파일은 건드리지 않는다
4. **자동 점검**: 시간이 되면 핵심 동작을 확인하는 짧은 테스트를 만들어 돌린다(pytest, 없으면 unittest). 결과 숫자(통과/실패)를 보여 준다.
5. **정리**: 디버그용 출력, 안 쓰는 파일, 비밀값이 없는지 확인한다. 과제가 제공한 파일은 건드리지 않는다. 과제 폴더의 `AGENTS.md`, `cofa-skills/`, `WORKLOG.md`는 내가 AI에 준 지침과 기록이므로 지우지 않는다.
6. **결과 문서** 작성
   - **과제가 제출 문서의 이름과 양식을 정했으면 그 양식을 그대로 쓰고**, 아래 내용은 양식의 알맞은 칸에 나눠 담는다. 양식에 없는 칸을 만들지 않는다. 해당하지 않는 칸은 과제가 정한 방식대로 적는다.
   - 정한 것이 없으면 README.md에 쓴다. 과제가 제공한 README.md가 이미 있으면 덮어쓰지 말고 RESULT.md에 쓴다.
   - 제출 문서에는 "초안", "사용자", "에이전트", "검토 예정" 같은 작업 메모를 쓰지 않는다.
   - **내 판단이나 경험을 서술하는 문서는 문장을 쓰지 않는다.** 사례 후보 표만 만든다(PROMPTS P11).
   - 담을 내용
     - 문제 정의: 합의문을 바탕으로 누구의 어떤 문제인지 한두 문장, 성공 기준과 충족 여부
     - 해결 방법: 구조 3~5줄
     - **핵심 결정 2~3개**: 각각 *고른 것 / 이유와 출처(요구사항, 담당자 답변) / 버린 대안*. WORKLOG 결정 기록과 AI 제안 수정 기록에서 가장 중요한 것을 고르고, 이유는 **내가 쓴 표현 그대로** 옮긴다. 기록에 없는 결정이나 이유를 지어내지 않는다.
     - **요구사항과 코드 대조표**: 요구사항 번호 / 구현 위치(파일·함수) / 확인 방법. 짧은 표 하나
     - 실행 방법: 실행 스크립트 한 줄과 접속 방법. 2번에서 실제로 띄운 명령과 같아야 한다
     - 확인 방법과 결과: 실제로 실행한 것만
     - 한계와 장애 대응: 확인하지 못한 것, 범위에서 뺀 것과 이유, 담당자 재량으로 옵션에 둔 것. 데이터 이상이나 재시작 같은 장애 상황에서 지금 어떻게 동작하는지와 대응 방법. 실제로 확인한 것과 확인하지 못한 것을 구분해서 쓴다
     - 다음 단계: 시간이 더 있으면 할 일 1~3개
7. **WORKLOG.md 3분 요약** 채우기: 핵심 동작, 확인 방법, 내가 바꾼 결정. 10줄 이내로, 초보자가 소리 내어 읽을 수 있는 문장으로 쓴다.
8. 3분 요약과 결과 문서에 들어간 사실(파일 이름, 동작, 결과값)이 실제 코드와 실행 결과와 맞는지 대조한다. 다른 부분이 있으면 짚는다.

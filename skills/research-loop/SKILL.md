# 연구 루프

사용자는 초보자다. 목표는 **더 나은 결과를, 사용자가 설명할 수 있는 방법으로, 근거와 함께** 얻는 것이다.
바퀴마다 결론을 낸다. 판단은 사용자가 한다. 예상만으로 비교하지 않고 **실측**한다.

## 지켜야 할 것
- **기준선을 망가뜨리지 않는다.** 새 방법은 옵션(조절 값이나 전략 이름)으로 붙인다. 기본값은 사용자가 채택할 때만 바꾼다. 바퀴마다 커밋한다.
- **규칙 위반이 생기는 안은 채택 후보가 아니다.** 검사기 위반 수를 표에 항상 넣는다.
- **설명할 수 없는 방법은 제안하지 않는다.** 가설마다 "초보자에게 한두 문장으로 설명하면" 칸을 붙인다.
- 출력은 표 중심으로 짧게. 긴 로그는 파일로 남기고 경로만 말한다.

## 0. 준비 (기준선 구간에서 만든다)
사용자가 "research-loop 준비"를 요청하면:
1. **목표와 지표**: WORKLOG "목표와 지표" 칸에 지켜야 하는 것 / 좋게 할 것(담당자가 말한 기준) / 줄일 것을 적는다. 지표마다 계산 방법 한 줄과 출처(담당자 답, 요구사항).
2. **평가 도구**: 데이터셋과 조절 값을 받아 **지표 표와 규칙 위반 수를 한 번에 출력**하는 명령을 만든다. 규칙 위반은 결과 파일만 읽는 별도 검사기로 센다(계산 코드를 쓰지 않는다).
3. **평가 세트**: 빨리 돌릴 대표 사례 2~3개(평소 경우, 특이한 경우)를 고르고 이유를 적는다. 기준선으로 한 번 돌려 **1회 실행 시간**을 재서 WORKLOG에 적는다. 한 번에 수 분 이상 걸리면 더 줄인다.
4. 기준선의 지표 표를 보여 준다. 제공 데이터에 지금 상태(기존 결과)가 있으면 같은 지표로 나란히.

## 1. 알아가기 (첫 바퀴 전 한 번. 점검·분석 창에서 해도 된다)
- 이 문제가 어떤 종류인지 한두 문장. 흔히 쓰는 접근 2~3개를 "내가 설명할 수 있나 / 구현 난이도 / 기대 효과"로 비교.
- 결과를 바꾸는 **조절 값** 목록. 각각 올리면 무엇이 좋아지고 무엇이 나빠지는지.
- 기준선 지표에서 **가장 나쁜 곳**과 그 이유 후보. 첫 가설은 여기서 나온다.

## 2. 한 바퀴
**요청 ① 가설**: 가설 3개를 표로 낸다.
| 가설 | 바꿀 것 (조절 값·방법) | 좋아질 지표 | 나빠질 수 있는 지표 | 구현 난이도 | 초보자에게 설명하면 |
|---|---|---|---|---|---|
추천 하나와 이유 한 줄. 사용자가 고를 때까지 기다린다.

**요청 ② 실험 (한 번에 끝까지)**: 사용자가 고르면
1. 옵션으로 구현한다 (기본값 그대로)
2. 평가 세트로 기준선과 새 방법을 돌린다. 조절 값이 있으면 3~5개 값으로 돌린다
3. 표를 낸다: 행 = 기준선과 각 설정, 열 = 지표와 규칙 위반 수, 1회 실행 시간
4. 눈에 띄는 점 두 줄 (사실만), 쉬운 말 2줄 (무엇을 바꿨고 어떻게 동작하는지, 파일·함수 이름 하나)
5. 커밋한다
오래 걸려도 중간에 멈추지 않는다. 다만 진행 상황을 짧게라도 출력한다.

**사용자 판단**: 사용자가 결론 한 줄(채택 / 기각 / 보류와 이유)을 보내면 그대로 실험 기록에 적는다.
- **선호가 갈리는 결과**(어떤 지표는 좋아지고 어떤 지표는 나빠짐)면 담당자에게 물을 **숫자 DM 초안**을 쓴다: 표에서 두세 안을 골라 "A안은 …, B안은 …. 어느 쪽이 맞나요? 정하기 어려우시면 화면에서 고르실 수 있게 두겠습니다." 숫자는 표에서 그대로 가져온다.
- 담당자가 정하지 못하면 쓰는 사람이 바꿀 수 있는 옵션으로 두고 기본값을 정한다.
- 채택이면 기본값을 바꾸고 다시 커밋한다.

**기록**: WORKLOG "실험 기록"에 한 줄. 바퀴 / 가설 / 바꾼 것 / 결과(기준선 대비) / 사용자 결론 / 담당자 답.

## 3. 멈추는 조건
- 사용자가 "남은 1시간쯤"이라고 하면 새 바퀴를 시작하지 않는다. 진행 중인 실험은 결과가 나오면 기록하고, 안 나오면 보류로 적는다.
- 두 바퀴 연속 채택이 없으면 멈추자고 제안한다.

## 4. 끝내기
1. 채택안(현재 기본값)으로 **전체 데이터**를 돌려 검사기 위반 0과 실행 시간을 확인한다.
2. 실행 안내 문서의 설계 기준·최적화 설명에 넣을 **요약 표**를 만든다: 기준선 vs 채택안(지금 상태가 있으면 그것도), 기각·보류한 가설과 이유, 나빠진 지표와 그 이유, 담당자 재량으로 둔 옵션.
3. 문장은 표와 실험 기록에 있는 사실만 쓴다. 나빠진 지표를 숨기지 않는다.

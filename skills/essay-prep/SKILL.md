# 서술형 대비 카드

서술형은 제출물(코드, WORKLOG, 결정 기록, 제출 문서)에서 만들어진 질문이 나온다. 제출 뒤에는 화면을 볼 수 없으므로 사용자는 **제출 전에 이 카드를 외운다.**
정확한 숫자보다 **무엇을, 왜, 어떻게 확인했고, 무엇을 안 했는지**를 자기 말로 말할 수 있는 것이 목표다.

## 지켜야 할 것
- **사실만 모은다.** WORKLOG, 결정 기록, 실험 기록, AI 제안 수정 기록, 검증 기록, 코드, 제출 문서에 있는 것만 쓴다. 없는 것은 지어내지 않는다.
- **이유는 사용자의 말을 그대로 옮긴다.** 기록에 사용자 표현이 없어서 내가 요약한 줄 끝에는 `(요약)`을 붙인다. 사용자가 외우기 전에 자기 말로 고친다.
- **답안 문장을 쓰지 않는다.** 줄마다 짧은 사실과 키워드만. 서술형 답은 사용자가 쓴다.
- 숫자는 필요 없다. 크기만 말하면 된다 (예: "크게 줄었다", "0건").
- 전체 60줄 이내. 넘으면 덜 중요한 것을 뺀다.
- WORKLOG 맨 아래 "서술형 대비 카드" 칸에 쓴다. 이전 카드가 있으면 고쳐 쓴다.

## 카드 구성
1. **한 줄 요약** (2줄): 누구의 어떤 문제를, 무엇으로 풀었나
2. **흐름 5줄**: WORKLOG "코드 흐름 메모"의 내 한 줄들을 순서대로 잇는다. 각 줄에 파일·함수 이름 하나
3. **꼭 말할 이름 5개**: 답에 넣으면 구체성이 생기는 이름 (파일, 함수, 화면, 데이터 파일, 검사기·테스트)
4. **6유형 카드** (유형마다 4줄: 결론 / 근거(이름) / 이유(내 말) / 비용·안 한 것·확인 위치)
   - 선택과 비용: 가장 중요한 결정 1~2개, 버린 안과의 차이, 감수한 비용과 관리
   - 흐름과 책임: 단계별로 무엇이 무엇을 받아 무엇을 넘기나
   - 실패할 때 동작: 잘못된 입력, 중간 상태(적용했지만 다시 계산 전 등)에서 보장되는 것과 안 되는 것
   - 조건이 바뀔 때: 설정값 변경, 한계 초과, 대안을 합칠 때 결과가 어떻게 바뀌고 위험을 어떻게 막거나 드러내나
   - 독립 검증: AI 결과를 그대로 믿지 않고 확인한 방법(별도 검사기, 원본 대조, 내가 직접 본 것), 나빠진 것, 다음 개선
   - AI 협업 과정: 제출 문서에 쓴 사례마다 발견 → 원인 좁히기 → AI 제안 중 받아들인 것·고친 것·버린 것 → 근거가 된 검사
5. **상황별 동작표**: 상황 / 어떻게 되나 / 어디서 (파일·함수·테스트) / 안 되는 것
6. **구현하지 않은 것과 이유**: 3~5개. 범위에서 뺀 것, 확인 못 한 것, 담당자 재량으로 둔 것
7. **예상 질문 6개**: 위 6유형마다 하나씩, 이 제출물의 실제 내용을 짚어서. 답은 쓰지 않는다

## 끝나면
- `(요약)` 표시가 붙은 줄 수를 알려 주고, 사용자가 자기 말로 고칠 줄을 짚는다.
- 사용자가 예상 질문에 기억으로 답을 쓰면 **사실과 다른 부분, 질문의 하위 물음 중 빠진 것**만 짚는다. 문장은 고치지 않는다.
